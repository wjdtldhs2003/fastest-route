# 가장 빨리 도착하는 길찾기

기존 길찾기가 말하는 "가장 빠른 길"이 아니라, 지금 나서면 실제로 가장 빨리 도착하는 길을 찾는 서울 대중교통 길찾기입니다. 그러려고 기존 길찾기가 안내하지만 실제로는 놓치기 쉬운 환승을 걸러 내고, 갈아탈 곳에서 기다리는 시간까지 계산합니다. 엘리스AI 챌린지 2026 출품작(PoC)입니다.

- **놓치기 쉬운 환승:** 기존 길찾기 방식(초속 1.25 m로 걷고 신호 대기 0)이 안내한 환승 차량을, 사람마다 다른 걷는 속도와 신호 대기, 차가 떠나기 30초 전까지 정류장에 닿아야 하는 승차 여유로 다시 계산했을 때 탈 확률이 40% 미만인 환승.
- 앱은 걷는 속도와 신호 위상을 확률변수로 두고 준난수 표본 4,096점으로 여정마다 탈 확률과 도착 분포를 계산해, 평균 도착이 가장 이른 길을 고릅니다.
- 확률은 앱이 계산하고, 화면은 결정만 말합니다: "탈 수 있습니다", "빠른 걸음이면 탈 수 있습니다", "놓칠 수 있습니다", "늦어도 11:53에는 도착합니다".

## 화면

- **소개 (첫 화면):** 화면 한 장에 메시지 하나씩 내려 보는 소개입니다. 토요일 16:13 실제 장면(기존 안내 16:23 도착 → 실제 16:41, 이 앱 16:26)을 같은 시간 막대로 맞대고, 휴대폰 화면 셋과 실제 기록으로 확인한 숫자를 보인 뒤 "길찾기 시작"으로 들어갑니다. 주소 끝에 `?page=app` 을 붙이면 소개를 건너뜁니다.
- **간단히 보기 (길찾기):** 몇 분 걸려 몇 시에 닿는지, 지금 할 일, 무엇을 어디서 타고 내리는지, 놓치면 어떻게 하면 되는지, 기존 길찾기 앱 1위와 이 앱 추천을 같은 시간 막대에 맞대어 몇 분 먼저 닿는지와 기존 1위가 늦는 까닭을 쉬운 말로 보입니다. 휴대폰 너비에 맞췄습니다. 처음에는 선릉역 북쪽 출구에서 청담역 근처까지, 지하철을 두 번 타고 따릉이로 마무리하는 길이 열립니다. 왼쪽(휴대폰은 "출발·목적지 바꾸기") 예시 경로와 장소 목록에서 바꿀 수 있습니다.
- **실제 기록 장면:** 소개 페이지의 장면 단추를 누르면, 수집한 실제 버스 도착·따릉이 기록에서 고른 그 시각으로 길찾기 화면이 열립니다. 장면 자료가 있는 판에서만 보입니다.
- **안내 모드:** "이 경로로 안내 시작"을 누르면 화면이 켜져 있는 동안 1분마다 다시 계산해, 타려던 차를 놓치기 쉬워지면 알리고 더 빠른 길을 권합니다. "탔어요"를 누르면 휴대폰 위치 대신 탄 차의 운행으로 계산합니다.
- **지금 위치에서 출발:** 휴대폰 위치가 준비된 지역(강남역, 삼성역 둘레) 안이면 그 자리에서 출발합니다. 위치는 계산에만 쓰고 파일이나 기록에 남기지 않습니다. 휴대폰 위치는 https 주소에서만 받을 수 있습니다.
- **자세히 보기:** 기존 방식 1위와 이 앱의 추천을 초 단위로 비교하고, 탑승별 탈 확률, 신호 대기, 따릉이가 남아 있을 확률, 요금, 탐색 과정을 탭별로 보입니다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

- Python 3.13 에서 확인했습니다. 엔진 자체 검사 `python core_engine.py --selftest` 160/160, 탐색 조합 검사 `--matrix` 144/144, 화면 검사 `python app.py --uitest` 43/43, 명세에서 따로 짠 검산 `check/run_all.py` 38/38.
- 키 없이 열면 시뮬레이션 모드(실제 정류장과 노선에 설계한 도착 시각)로 돕니다. 데이터 폴더에 수집 기록이 있으면 기록 재생 모드도 쓸 수 있습니다.
- 실시간 모드는 환경변수 `SEOUL_OPENAPI_KEY` 나 `DATA_GO_KR_SERVICE_KEY` 가 있을 때 쓸 수 있고, 카카오 도보 경로 비교는 `KAKAO_REST_API_KEY` 가 있을 때 됩니다. Streamlit Community Cloud 에서는 앱 설정의 Secrets 에 같은 이름으로 넣습니다(맨 위 수준의 값은 환경변수로도 읽힙니다). 키를 이 저장소나 주소에 넣지 마세요.
- 데이터 폴더는 환경변수 `MOBILITY_ROUTER_DATA_DIR` 가 있으면 그 폴더, 없으면 `app.py` 옆의 `data/` 입니다.
- 전체 수집 기록은 저장소에 올리지 않습니다. 공개 시연판에는 실제 기록 장면마다 앞 20분, 뒤 10분의 버스 도착 예측과 따릉이 관측만 옮긴 작은 기록을 둡니다(호출 기록과 키는 담지 않습니다).

## 한계

- 범위는 강남구의 두 구간(강남역에서 신사역 방향, 선릉역에서 청담역·삼성동 방향)과 그 둘레입니다.
- 강남구 신호는 실시간 자료가 없어(전국 신호 API 에 강남구 값이 없음, 2026-11-21 확인) 설계한 주기와 녹색 시간으로 계산합니다. 실시간 모드에서 서울 t-data 키(`SEOUL_TDATA_API_KEY`)가 있으면 세종대로 시범 구간 교차로는 실시간 잔여 시간을 씁니다.
- 버스 도착 시각은 공공 API 의 예측을 그대로 씁니다(예측이 틀리는 만큼은 계산에 넣지 않습니다).

## 자료

버스 실시간 도착 예측(공공데이터포털), 지하철 시각표, 따릉이 실시간 대여 정보, 교차로 신호(서울 열린데이터광장·서울 t-data), 보행망(OpenStreetMap, © OpenStreetMap contributors).

## 생성형 AI 활용

기획과 문제 정의는 사람이 했습니다. 자료 수집 도구, 확률 공식의 계산, 웹앱 개발(설계 명세, 코드, 시험과 검산)에 Claude(Anthropic)를 썼고, 외부 자료 조사는 아스트라에 맡겨 검수한 뒤에만 썼습니다. 앱이 실행될 때는 생성형 AI를 부르지 않습니다.
